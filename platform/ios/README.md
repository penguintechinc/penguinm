# platform/ios/

Dormant. iOS is second-class for the lifetime of this spec revision: every app's
`ios/` directory (generated by `flutter create --platforms android,ios`) is kept in the
repo so app scaffolding doesn't need to be redone later, but it gets no CI job, no
signing, no App Store work, and no shared convention files here yet.

## What activates it

Per spec §1 ("Platform priority") and §12 ("Follow-ups outside this repo"), iOS work
starts only after:

1. Android has shipped for at least one app end-to-end (build, sign, release pipeline
   green) — `apps/penguin_reference` is the proving app.
2. A written decision to invest in iOS signing/provisioning (Apple Developer Program
   enrollment, certificates, `Info.plist`/entitlements conventions) is made explicitly —
   this is a cost and process commitment, not a code change.
3. A follow-up spec is written for the `platform/ios/` equivalent of
   `platform/android/`: shared Xcode build settings, a signing convention (env-only,
   mirroring `platform/android/gradle/signing.gradle.kts`), and CI (`e2e-ios.yml` or
   equivalent).

Until then: do not add Swift native modules, do not wire `ios/` into any CI workflow,
and do not commit signing certificates or provisioning profiles anywhere in this repo
(`client.md` Authentication & Tokens / Secrets & Credentials still apply once iOS work
starts — code signing required for iOS production, developer certificates only, never
committed).
